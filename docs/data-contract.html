Canonical data contract

The stable intermediate structure used by the Sub-population Fairness & Readiness Auditor for CCDI to validate synthetic or user-supplied cohorts before readiness, care-gap, and model-fairness analysis.

← Return to the Auditor
Demonstration boundary. This contract is informed by public CCDI descriptions but is not an official CCDI submission template. Mapping to a selected CCDI resource requires version confirmation and review with NCI/CCDI.
InputOne row per participant

Canonical CSV or JSON with 22 required fields for the current demonstration workflow.

ValidationStructure before analysis

Required columns, unique identifiers, value ranges, binary indicators, and accepted categories.

PrivacyBrowser-local processing

Uploaded records remain in the browser. The public demonstration should never receive controlled-access data.

How the contract is used

  1. Ingest
    Read canonical CSV/JSON and preserve stable participant identifiers.
  2. Validate
    Stop or flag analyses when required structure, categories, or values are invalid.
  3. Audit
    Apply consistent population, eligibility, outcome, prediction, and missingness definitions.
  4. Export
    Create synthetic node bundles and disclosure-conscious aggregate audit reports.
  5. Map
    Crosswalk canonical fields to a selected CCDI model, terminology set, and version.
  6. Test
    Use synthetic fixtures and automated checks to verify future adapter behavior.

Missing values

Blank CSV values and JSON null values are treated as missing where permitted. Missing is kept distinct from “no,” “not eligible,” and “care not completed.” Analyses report relevant denominators and do not automatically interpret undocumented care as care not received.

Accepted values

Binary indicators use 0 and 1. Predicted risk must fall between 0 and 1. Age and follow-up fields must remain within documented ranges. Categorical fields use the enumerations in the machine-readable schema.
